# 知径 · 项目基调

> **知径是我一个人的线上自习室。**
> 打开它，是为了让自己坐下来、学进去；不是为了让别人来用。

这份文档回答两个问题：**知径为什么存在，以及它永远不做什么。** 功能会变，场景会换，AI 会升级，但下面这些不轻易变。

## 0. 效力

- 本文优先于路线图、需求单、设计稿和外部调研。冲突时，以本文为准。
- 与基调冲突的功能，默认不做；真要做，先改本文并写明理由。
- 每个新功能、每次代码审查，用第 9 节的清单过一遍。
- 本文不规定“怎么实现”，只规定“为什么做、做到什么程度、绝不做什么”。

## 1. 底色：一个人的软件

知径只有一个用户：我。

这不是“先做单人版，以后转多人”的过渡形态，而是最终形态。由此推出几条硬约束：

- 没有账号、注册、登录、找回密码、多租户、角色权限、运营后台。
- 没有社交关系、好友、私信、动态、排行榜、学习社区。
- 没有多人房间、连麦、摄像头、虚拟形象、主持人角色。
- 没有为了“留住用户”而做的签到、红点、推送、等级、会员。
- 没有商业化：不收费、不投放、不做增长实验。

“一个人的软件”不是简陋，而是**可以偏科**：可以只服务我的学习习惯，可以为我常用的平台硬编码，可以删掉用不上的配置项，可以不为陌生人的浏览器、系统、网络环境做兼容承诺。省下来的复杂度，全部投到“我每天愿不愿意打开它”上。

开源只意味着代码公开、别人可以看和自部署，**不意味着知径变成公共产品**：不承诺支持、不承诺兼容、不接多用户需求、不设路线图投票。

## 2. 定位：一间只属于我的自习室

知径不是课程平台、不是笔记软件全家桶、不是 AI 聊天工具，也不是学习社区。

它是一间收拾干净的书房：**一张安静的书桌 + 一个可信的计时器 + 一个不打扰的笔记本 + 一个随叫随到的 AI。**

当前已经具备的基石：

| 部分 | 现在 |
| --- | --- |
| 场景 | 六款内置场景，支持导入自己的 ZIP 主题包（背景、动态视频、封面、可选环境音），可沉浸显示 |
| 节奏 | 专注 / 短休息 / 长休息，时长可调；记录今日专注分钟与轮次 |
| 声音 | 本地歌单，白 / 粉 / 棕噪音与主题环境音，独立音量 |
| 看课 | 粘贴 B 站链接边看边记，分 P、时间戳、续播点，Markdown 自动保存到本机 SQLite，可导出 Obsidian 或下载 |
| AI | 已有流式润色与整理接口；界面接入与学习工作流属于后续延展 |
| 数据 | 本机 SQLite、浏览器偏好、可备份；默认无遥测 |

这些功能共享同一条主线：**减少开始学习的阻力，保护已经进入的专注。**

## 3. 核心体验：不可妥协的六件事

1. **打开即专注。** 首页就是自习室，不是登录页、仪表盘或功能大厅。从打开到开始一轮专注，三次操作以内。
2. **计时器是唯一常驻的强信息。** 其他控件在需要时出现，不需要时退后；不做挡住视频的全屏遮罩，不做会跳动、抢焦点的装饰。
3. **安静。** 低饱和、低动效、无弹窗轰炸、无通知、无红点、无自动播放。系统开启“减少动效”时，背景动效和过场全部降级。
4. **不打断正在发生的事。** 切换场景、调声音、进出看课笔记，专注计时、播放中的声音、课程草稿和撤销记录都不中断。
5. **数据是我的，而且不会丢。** 自动保存、本地草稿兜底、冲突时保留原文件、可导出、可备份；断网也能完成一轮专注和一篇笔记。
6. **AI 是助手，不是房间的主人。** 只有我调用时它才出现；结果先预览、再决定是否写入；不后台改写笔记；失败时安静退回手动编辑，不阻塞任何核心流程。

## 4. 功能版图

### 4.1 基石（必须一直好用）

- 自习室主界面：专注计时、本轮目标、学习待办、今日专注统计。
- 场景与主题包：内置场景、导入 / 预览 / 应用 / 删除自己的主题、沉浸模式。
- 声音：本地歌单、环境噪音、主题环境音，独立音量与记忆。
- 看课笔记：B 站视频与分 P、时间戳、续播点、自动保存、Obsidian 导出、Markdown 下载、草稿恢复与冲突提示。
- 本地数据：SQLite 迁移、备份与恢复、数据目录可配置。
- 可用性：深浅色、320px 窄屏、键盘操作、焦点可见、减少动效。
- 启动：本机一条命令可运行，Docker 自部署可选。

### 4.2 延展（顺着基调长）

- **通用笔记与目录**：独立于课程的笔记，资源管理器式目录浏览，可关联课程或资料。
- **资料库与检索**：本地资料入库、全文搜索、能打开来源；耗时的解析给可查看的后台进度。
- **智能体学习工作流**：基于当前笔记与所选资料问答、整理、制定与复盘学习计划；结果先预览再写入。
- **主题与备份体验**：更顺手的主题包制作说明、备份与换机恢复。
- **无障碍与窄屏**：持续补齐，而不是一次性的“适配完成”。

延展功能也必须遵守第 3 节；任何一条做不到，就先回到基石。

### 4.3 非目标（明确不做）

| 想做的东西 | 决定 | 原因 |
| --- | --- | --- |
| 多人自习房间、连麦、摄像头、虚拟座位、主持人 | 不做 | 服务的是“和别人一起学”的需求；我要的是一个人的空间。调研里的“影子房间 / 联机小房间”不采纳。 |
| 好友、社区、排行榜、打卡挑战、学习时长公开 | 不做 | 比较和社交压力会破坏专注；今日统计只给自己看。 |
| 账号、云同步服务、团队空间 | 不做 | 单人单机；多设备用备份文件或导出解决。 |
| 付费、会员、广告、增值功能 | 不做 | 自己用的工具不需要商业模式。 |
| 课程市场、版权视频、绕过平台的下载或去广告 | 不做 | 只做“打开我本来就在看的课并记笔记”，不碰内容分发。 |
| “支持所有视频网站” | 按需 | 只为我在用的平台做，不承诺通用适配。 |
| 换装、宠物、小游戏、成就墙 | 不做 | 游戏化会稀释“安静书桌”的调性。 |
| AI 首页、AI 主动搭话、自动后台改写全部笔记 | 不做 | 笔记是我的思考痕迹；AI 只在我明确要求时就地帮忙。 |
| 大而全的知识库 / 多功能工作台 | 克制 | 先服务真实的学习流程；没有真实需求不新增一级入口。 |
| 手机 App、多端原生客户端 | 暂不做 | Web 已覆盖主要场景；确有必要先考虑 PWA 或轻壳。 |
| 遥测、埋点、第三方分析 | 不做 | 本地优先，不拿自己的数据换统计。 |
| 主题分享社区 / 主题市场 | 不做 | 公开格式、文件自己传即可；不做审核、排行和运营。 |

判断一个新需求时，先看它是否落在这张表里。落在这里的，不用讨论实现，直接不做。

## 5. 设计基调

**视觉：像一间安静的书房，不是游戏大厅。** 暖木色、低饱和绿、雾面质感；不出现大面积纯白，不用高频动效和刺眼的高对比红黄。红色只用于“即将结束”和错误，绿色只用于“完成”。场景图上压文字必须加遮罩，保证可读；计时器字号要大到余光可读，但不压在人脸或画面主体上。

**文案：平实、简短、像便签。** 按钮直接说动作（“开始专注”，不是“开启沉浸式心流之旅”）；错误说清原因和下一步；不用“赋能、闭环、极致体验”这类营销词，也不用感叹号堆情绪。

**交互：默认不打扰。** 键盘可达、焦点可见、Escape 能退出、返回路径清楚；不做只有隐藏手势才能打开的功能；窄屏 320px 仍能完成主要操作；所有操作都不劫持滚动、不突然抢焦点、不弹无法关闭的层。

**声音：默认安静。** 播放是显式动作，不自动出声；音量和选择可记忆；环境音、歌单、主题环境音互不抢占；出错时安静停止并说明，不反复重试。

## 6. 技术基调

- **形态**：模块化单体。FastAPI + Vue 3 + TypeScript + Vite + Pinia + SQLite；前端构建产物由后端托管，单进程可跑。
- **简单优先**：不引入 Redis、Postgres、消息队列、微服务、账号服务。新增依赖必须说明“为什么非得它不可”，能删就删。
- **单人模型**：不为并发协作、权限、租户写代码；不为想象中的规模做抽象。
- **数据安全**：迁移向前兼容，升级不丢数据；写入原子化；备份必须真的能恢复；冲突时保留而不是覆盖。
- **AI 可替换**：只依赖 OpenAI 兼容接口，密钥走环境变量；模型失败、超时、限流时优雅降级，核心流程不依赖它。
- **验证**：ruff、pytest、eslint、prettier、vitest、前端构建和 OpenAPI 类型一致性；改接口就同步生成类型。
- **部署**：本机优先，Docker 可选；数据目录可配置、可挂载；不把状态藏在容器里。
- **许可**：PolyForm Noncommercial License 1.0.0；迁入的材料继续遵守原许可。

## 7. AI 的边界

AI 是知径的“第二只手”，不是新的产品中心。

**可以做的：**

- 对当前笔记做润色、整理格式、提炼结构。
- 基于当前笔记和所选资料问答，回答里注明依据。
- 辅助制定学习计划、复盘一次学习、出练习题。
- 数学定义、概率、评分、损失、更新、复杂度和推导使用 LaTeX；真实程序实现与命令保留代码。

**必须遵守的：**

- 只在我触发时调用；只发送当前任务需要的上下文，不上传整个资料库。
- 写入笔记前先预览，我可以拒绝或撤销；不覆盖未保存草稿，不自动合并冲突。
- 断网、超时、模型报错时安静退回手动编辑，保存和计时不受影响。
- 不记录到第三方分析，不把对话当成需要运营的数据资产。

**不做的：**

- AI 首页、AI 主动搭话、AI 自动整理全部笔记。
- 用积分、额度、会员来包装 AI。
- 让 AI 替我做“要不要做某个功能”的产品决定。

## 8. 怎样算做对了

知径的成功标准是主观的，但可以检验：

- 我每天都愿意打开它；打开到开始专注不超过 10 秒、3 次操作。
- 一次 25 分钟的专注里，没有被界面打断过。
- 笔记没有丢过；换一台电脑能用备份恢复。
- 断网时仍能完成一轮专注并写下笔记。
- 三个月后还在用，而且首页没有为了“看起来丰富”而增加的入口。
- 不需要读说明书就能用。

反指标同样明确：需要教程才能开始、首页出现第二个抢注意力的主入口、为了“留存”加提醒或签到、功能多到我不敢打开。

## 9. 防偏离检查清单

每做一个新功能、每次代码审查，先回答这六个问题：

1. 它服务的是“我一个人坐下来学习”吗？
2. 它让开始更简单，还是增加了配置、选择或等待？
3. 它是否引入了账号、网络依赖、多人语义或运营中的任何一项？
4. 断网、无 AI 时，核心流程还能用吗？
5. 数据能导出、撤销、恢复吗？
6. 删掉它会影响其他功能吗？能独立删除，才容易长期维护。

如果这个功能只有“别人来用”才有意义，答案已经是否。

**冲突裁决顺序：** 我的当次明确要求（若改变基调，先更新本文）> 本文 > AGENTS.md 的项目约定 > docs/development-plan.md 的路线 > 外部调研与参考 > 单条建议。

**几个常见的诱惑，提前回答：**

- “加个好友一起自习吧？”——不加。陪伴感由场景、声音和计时提供，不需要另一个人。
- “接个云同步吧？”——不做云服务。用备份文件、导出和系统级文件同步。
- “做个连续打卡 / 排行榜吧？”——不做公开比较。只保留给自己看的今日统计。
- “把 AI 放到首页吧？”——不放。AI 在笔记和资料里按需出现。
- “支持更多视频网站吧？”——以我实际在看的平台为准。
- “做成手机 App 吧？”——先不做。Web 够用再说。
- “别人提了需求，顺手做了吧？”——不做。开源不改变单人定位。

## 10. 开源与分享

- **目的**：留档、给未来的自己看、让别人参考或自部署。不是获客，不是做产品。
- **边界**：不做公开服务，不接定制，不承诺 issue 响应；改变定位的 PR 直接拒绝。
- **README 必须写清**：单人自用、非商业许可、无支持承诺、自部署与备份方式。
- **数据卫生**：示例、文档、截图和测试只用合成数据；不提交本机资料、密钥、数据库备份和真实笔记。
- **贡献**：修 bug、无障碍改进、文档修正欢迎；多人、社交、商业化方向不进入路线。
